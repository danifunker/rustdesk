HOW TO RUN THE AGENT ON THE G5
==============================

The machine:  ssh ppctiger   (admin@192.168.99.116)
Connect from a RustDesk client by typing  192.168.99.116  into the ID field
(no port). Password: ppctest123. Sessions in direct-IP mode are UNENCRYPTED,
which is also upstream's behaviour for direct connections.


THE SIMPLE WAY: over ssh
------------------------

    ./build-ppc.sh deploy

Builds, installs, and starts the agent inside a detached `screen` session, which
keeps running after the ssh connection closes.

The screen matters. A *fully* detached agent -- backgrounded with `&`, or with
nohup -- cannot reach the window server at all:

    kCGErrorRangeCheck : On-demand launch of the Window Server is allowed for
                         root user only
    Window Server is not available.

It then reports a 0x0 display and quietly serves an input-only session: mouse
and keyboard work, no video ever arrives. Started under screen it keeps enough
of the login session to read the framebuffer, verified by streaming frames after
the ssh connection was closed.

To look at it, or stop it:

    ssh ppctiger 'screen -r rdagent'      # detach again with ctrl-a d
    ssh ppctiger 'screen -S rdagent -X quit'


AFTER A REBOOT: as a LaunchAgent
--------------------------------

A screen session does not survive a reboot. For the agent to come back by
itself, load it into the GUI session once -- in Terminal.app ON THE G5 ITSELF,
not over ssh, which reaches a different launchd:

    launchctl load -w ~/Library/LaunchAgents/com.rustdesk.ppc-agent.plist

After that the agent starts automatically at every login, and launchd restarts
it if it dies. To stop it:

    launchctl unload -w ~/Library/LaunchAgents/com.rustdesk.ppc-agent.plist

The plist lives in deploy/com.rustdesk.ppc-agent.plist in this repo; install it
with

    scp deploy/com.rustdesk.ppc-agent.plist \
        ppctiger:~/Library/LaunchAgents/com.rustdesk.ppc-agent.plist


NEVER CAPTURE THE DISPLAY
-------------------------

Reading the framebuffer needs no CGDisplayCapture, and adding one does real
damage. It takes exclusive control of the display and registers the caller as an
application:

    CGDisplayCaptureWithOptions -> CGSRegisterProcessAsApp -> _RegisterApplication
      -> LSClientSideSharedMemory::GetClientSideSharedMemory -> abort()

Run a few times a second, that steals focus and dismisses any menu open on the
G5 -- the machine becomes unusable to whoever is sitting at it. In a process
with no GUI session it aborts at that last frame instead, which is why an agent
started over ssh used to die the moment the connection closed.

It was added in the belief that the framebuffer mapping went stale. It does not:
measured over 140 s with nothing forced, six distinct screens, and every
in-process read matched a freshly exec'd one. See capture.rs.


RUNNING IT BY HAND
------------------

    ssh ppctiger '( ~/rustdesk-agent --port 21118 -vv > ~/agent.log 2>&1 < /dev/null & )'

Do NOT use nohup: over a non-tty ssh session Darwin's nohup dies with "can't
migrate to background session" and the agent never starts. The subshell above
exits immediately, which reparents the agent to init and survives the
disconnect.


BUILD AND DEPLOY
----------------

The key is passphrase-protected, so an ssh-agent has to hold it (once per
reboot of the Linux box):

    ssh-agent -a /tmp/ssh-agent-ppc.sock >/dev/null 2>&1
    SSH_AUTH_SOCK=/tmp/ssh-agent-ppc.sock ssh-add ~/.ssh/id_rsa

Then:

    ./build-ppc.sh            # build only      (~90 s incremental, ~14 min clean)
    ./build-ppc.sh deploy     # build, install and restart on the G5

If the LaunchAgent is loaded it owns the process, so let launchd restart it
rather than starting a second copy by hand -- the agent binds a fixed port and
the loser just fails. The C parts are compiled on the G5 itself by the
ppc-cc-remote.py wrapper, so the machine must be reachable to build at all.


CHECKING IT WORKS
-----------------

    ssh ppctiger '~/rustdesk-agent --probe-display'   # geometry and per-stage timings
    ssh ppctiger '~/rustdesk-agent --probe-live'      # capture liveness + mouse self-test
    ssh ppctiger '~/rustdesk-agent --probe-keys'          # prints the character -> keycode map,
                                                      # then types into whatever has focus
    ssh ppctiger '~/rustdesk-agent --probe-keys 1050 620' # click there first to take focus
    ssh ppctiger 'tail -f ~/agent.log'                # protocol trace, with -vv
    cargo test                                        # 32 host tests
    cargo run --example probe_client -- 192.168.99.116:21118 ppctest123

The agent serves ONE peer at a time, so probe_client fails while a real client
is connected. `--probe-live` and `--probe-keys` inject real events: they move
the cursor and type into whatever has focus on the G5.

The C probes under probes/ are for questions about the machine rather than the
agent (framebuffer behaviour, keyboard layout mapping):

    PPC_HOST=ppctiger probes/run.sh display-info

Verifying the keyboard is harder than it looks. Keystrokes go wherever the
focus is, so typing into the desktop tests focus as much as it tests the
mapping, and the passive alternative -- a listen-only CGEventTap -- needs
"Enable access for assistive devices" in Universal Access, which is off. That is
why `--probe-keys` prints the character -> keycode table first: it is the part
that can be checked without guessing. All 95 printable ASCII characters map.

Logs: ~/agent.log on the G5. Crash reports, which are worth reading when the
agent vanishes without a message, are in
~/Library/Logs/CrashReporter/rustdesk-agent_*.crash.
